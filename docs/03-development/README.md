## 🏗️ Project Architecture

### Tech Stack
- **Framework:** Next.js 15.1.4 (App Router)
- **Language:** TypeScript 5.7.3
- **Database:** MySQL + Prisma ORM
- **Authentication:** NextAuth.js
- **UI:** TailwindCSS + FontAwesome
- **State:** Zustand
- **Forms:** React Hook Form (planned)

### Folder Structure
```
src/
├── app/              # Next.js App Router
│   ├── (main)/       # Public pages
│   ├── (main-dashboard)/  # Admin pages
│   └── api/v1/       # API routes
├── components/       # Shared components
├── features/         # Feature modules
├── lib/              # Libraries & utilities
├── config/           # Configuration
└── middleware.ts     # Auth middleware
```

### Design Patterns
- **Route-based** for pages (Next.js App Router)
- **Feature-based** for business logic
- **Service Layer** pattern for API calls
- **Component-driven** UI development

## 🎯 Development Workflow

### 1. Create New Feature
```bash
# 1. Create feature folder
mkdir -p src/features/feature-name/{components,services,types}

# 2. Add service layer
# src/features/feature-name/services/featureService.ts

# 3. Add components
# src/features/feature-name/components/FeatureComponent.tsx

# 4. Add types
# src/features/feature-name/types/index.ts

# 5. Create API route
# src/app/api/v1/feature-name/route.ts

# 6. Add page
# src/app/(main-dashboard)/feature-name/page.tsx
```

### 2. Database Changes
```bash
# 1. Edit schema
# Edit prisma/schema.prisma

# 2. Create migration
npx prisma migrate dev --name migration_name

# 3. Generate client
npx prisma generate

# 4. Update TypeScript types
# Types are auto-generated by Prisma
```

### 3. Add New Component
```bash
# 1. Create component file
# src/components/ui/ComponentName.tsx

# 2. Export from index (if needed)
# src/components/ui/index.ts

# 3. Use in pages
# Import and use the component
```

## 🎨 Code Style

### TypeScript
- Use strict mode
- Prefer `interface` over `type`
- Use proper types, avoid `any`

### Components
- Use functional components
- Use hooks properly
- Follow naming conventions

### API Routes
- Always add authentication check
- Add proper error handling
- Return consistent response format

### Example
```typescript
// ✅ Good
export async function GET(request: NextRequest) {
    try {
        const session = await getServerSession(authOptions);
        if (!session) {
            return NextResponse.json(
                { error: "Unauthorized" },
                { status: 401 }
            );
        }

        const data = await fetchData();
        return NextResponse.json({ success: true, data });
    } catch (error) {
        console.error("Error:", error);
        return NextResponse.json(
            { error: "Internal Server Error" },
            { status: 500 }
        );
    }
}

// ❌ Bad
export async function GET() {
    const data = await fetchData();
    return NextResponse.json(data);
}
```

## 🔐 Security Guidelines

### Authentication
- ✅ Always check authentication in protected routes
- ✅ Verify user role (ADMIN/USER)
- ✅ Use getServerSession from next-auth

### API Security
- ✅ Add rate limiting to sensitive endpoints
- ✅ Validate all input data
- ✅ Sanitize user input
- ✅ Use proper error messages (don't leak info)

### File Upload
- ✅ Check MIME type (magic bytes)
- ✅ Limit file size
- ✅ Use unique filenames (UUID)
- ✅ Validate file content
- ✅ Restrict to ADMIN only

## 🐛 Debugging

### Common Issues

**Server won't start**
```bash
# Check if port is in use
lsof -ti:3000
kill -9 $(lsof -ti:3000)

# Check environment variables
cat .env

# Regenerate Prisma Client
npx prisma generate
```

**Database connection errors**
```bash
# Check MySQL is running
mysql.server status

# Test connection
mysql -u root -p

# Check DATABASE_URL in .env
```

**Type errors**
```bash
# Regenerate Prisma types
npx prisma generate

# Check tsconfig.json
```
